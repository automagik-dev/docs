# Genie CLI Reference

Engineering-internal dump of the command surface. `genie --help` is the only authority; this page exists so a reviewer
can read the whole surface at once without running the binary.

**Sixteen top-level commands.** Everything forks and exits — there is no daemon, no server, and no resident process.

```text
board  config  context  doctor  help   idea   init  install
mikro  orca    setup     shortcuts     task   uninstall
update wish
```

## Lifecycle: task

Per-repo task state over `.genie/genie.db` (SQLite, WAL, zero-daemon). Worktrees of one repository share the database
through `git rev-parse --git-common-dir`.

| Command | Purpose |
|---------|---------|
| `task create --title '<t>' [--agent <name> --why <reason>]` | Create a card. `--agent`/`--why` are a required pair; either alone is refused |
| `task list` | List cards, with filters |
| `task checkout <id> --worker <w>` | Atomically claim a ready card |
| `task move <id> --to <lane>` | Move a card to a lane its board defines. The flag is `--to`; `--lane` does not exist |
| `task heartbeat <id>` | Record liveness for a claimed card. Takes **no** `--worker` |
| `task status <id>` | Card detail, dependencies, stage log, declared assignment |
| `task set-wish <id> --wish <w>` | Attach or re-point wish identity (`--clear` removes) |
| `task assign <id> --agent <name> --why <reason>` | Declare or reassign the roster agent (`--clear` removes) |
| `task adopt <id> --board <ref> --lane <name>` | One-time placement of a pre-board card onto a lane |
| `task report <id> --worker <name> -- '<text>'` | The engineer's one handoff message per claim |
| `task comment <id> --worker <name> -- '<text>'` | Orchestrator gate pointer. Bounded to 4000 bytes, no control characters |
| `task block <id>` | Place an enforced block on a card — it refuses checkout until cleared |
| `task unblock <id>` | Clear an enforced block |
| `task release <id>` | Release a claim, returning the card to the ready queue |
| `task link <id> --wish <w>` | Link an existing card to a wish (appends a wish event) |
| `task delete <id>` | Hard-delete. Refused while other cards depend on it |
| `task done <id>` | **Orchestrator only.** Mark reviewed work done and recompute the ready set |
| `task export [--write]` | Emit the whole database as JSON; `--write` writes `.genie/roadmap.json` |
| `task import [--replace]` | Restore the database from `.genie/roadmap.json` |
| `task sync` | Three-way reconcile database ↔ snapshot. Run by four git hooks: `post-checkout`, `post-merge`, `post-rewrite`, `pre-commit` |

`--agent` names a roster agent (`claude`, `codex`, `pi`, `hermes`, `prime`). Assignment is **declaration-only** — there
is no checkout gate — and it serializes on the lane path only, so non-lane readers deliberately do not see it.

`task sync` resolution: when both sides moved but only card timelines differ, events are unioned by identity and
republished as `merged`. The card conversation is global state, not a local view. The four hooks that call it are
`post-checkout`, `post-merge`, `post-rewrite` and `pre-commit`.

## Spawn context

```bash
genie context [--wish <slug>] [--group <name>] [--plan] [--re-resolve]
```

Emits one line of versioned JSON: composed branch, resolved base SHA, and the ready set, which a spawn consumes.

| Flag | Effect |
|------|--------|
| `--wish <slug>` | Charset-restricted slug. Absent means the wishless integration-branch lookup |
| `--group <name>` | Requires `--wish` |
| `--plan` | Strictly read-only — writes nothing, including the recorded base |
| `--re-resolve` | Refresh the recorded base SHA instead of returning it. Requires `--wish` |

## Wish documents

```bash
genie wish lint [--dir <repo>]
```

Lints `<repo>/.genie/wishes` for structure in **any** repository and writes nothing.

| Exit | Meaning |
|------|---------|
| `0` | Clean |
| `1` | Findings — also the parser's own code for an unknown flag |
| `2` | **The root was refused.** A `--dir` you typed that is not a directory, or that holds no `.genie/wishes` |

`--dir` defaults to the git toplevel of the cwd, falling back to the cwd itself; a checkout that carries no wishes yet
is **not** an error and reports 0 files. A `--dir` you TYPED is verified instead, so a typo can never read as a clean
bill of health — which is why it is exit 2 and not exit 0. Treat 2 as a failure in CI.

## Microagents: mikro

```bash
genie mikro init
genie mikro call <agent> --prompt '<text>' [--dir repo] [--agents-dir dir] [--facts auto] [--boundary none|bwrap] [--raw]
genie mikro fixtures --from-commits
genie mikro bench <agent>
genie mikro coach <agent>
```

`call` declares **no options of its own**: the tail after the agent name reaches the runtime as typed, so a flag added
to the runtime needs no second edit in the CLI. One exception — genie's own global options (`-V`/`--version`,
`-h`/`--help`, `--no-interactive`) are consumed by the program wherever they appear, so `mikro call <a> --prompt -V`
prints the version and runs nothing. Quote the value or use `--prompt-file`.

Agent resolution, in order: `--agents-dir` → the **invoking** checkout's `.mikro/agents/<agent>/agent.yaml` (git
toplevel of the cwd, never `--dir`, which is the tree under review) → the release's `templates/mikro/agents`. The answer
names the winner in `agentSource`.

The run ledger goes to `<root>/.mikro/runs` only when the repository tracks a `.mikro/` directory (or is not a git
checkout at all); otherwise to `<GENIE_HOME>/mikro/runs/<basename>-<sha256(root)[:8]>`, so a repository that never
opted in grows no untracked files.

## Orca mirror

```bash
genie orca mirror --to <transition> --evidence '<text>' [--verdict <verdict>] [--worktree <selector>] [--json]
```

Writes genie's lifecycle onto the Orca **workspace card**, one way. One verb, because the map has to be code rather
than four prose recipes, and because the card must have exactly one writer.

| Flag | Required | Value |
|------|----------|-------|
| `--to <transition>` | yes | `APPROVED` \| `IN_PROGRESS` \| `REVIEW` \| `SHIPPED` \| `BLOCKED` |
| `--evidence <text>` | yes | One line naming the proof: group, head SHA, gap count, gate, merge SHA |
| `--verdict <verdict>` | only with `--to REVIEW` | `SHIP` \| `FIX-FIRST` \| `BLOCKED` — refused on every other transition |
| `--worktree <selector>` | no (default `current`) | `current` \| `active` \| `id:<repoId>::<abs path>` \| `path:<abs path>` \| `branch:<ref>` \| `name:<display name>` |
| `--json` | no | Accepted for symmetry; one JSON line is printed either way |

The transition → workspace-status map:

| `--to` | Orca `workspaceStatus` |
|--------|------------------------|
| `APPROVED` | `todo` |
| `IN_PROGRESS` | `in-progress` |
| `REVIEW` | `in-review` |
| `SHIPPED` | `completed` |
| `BLOCKED` | `in-progress` |

`BLOCKED` maps to `in-progress` deliberately: Orca has no blocked status, and the comment carries the word. The
comment is dated UTC, because a card comment is read in more than one timezone.

**Nothing here reads Orca.** A board status is never lifecycle truth, and there is no verb that brings one back — the
documents stay the record. The pure map lives in `src/lib/orca-lifecycle-mirror.ts` (no I/O); the spawn, the receipt
and the `worktree show` read-back belong to the closed adapter in `src/lib/orca-orchestration-adapter.ts`.

Exit codes are the contract:

| Exit | Meaning |
|------|---------|
| `0` | The write is **proven** — receipt identity plus the official read-back |
| `1` | A typed adapter failure. stderr carries one JSON line: `{error, operation, phase, retrySafety, recovery, reason}` |
| `2` | Usage — a refused transition, a missing or misplaced `--verdict`, or a selector outside the adapter's grammar |

An `invalid_argument` raised while *validating* is the caller's own input and exits 2 with the reason; every other
adapter failure is Orca's and leaves as the machine-readable line, so a coordinator can route it without parsing
prose. The map refuses first and at zero cost, then exactly one adapter call happens.

## Installation lifecycle

| Command | Purpose |
|---------|---------|
| `init` | Scaffold per-repo state; retire the `.codex/config.toml` marker block and the dead `.mcp.json` `genie mcp` entry, backup-first, preserving every other key byte-for-byte. A symlinked file is skipped |
| `install [--integrations <auto\|codex\|claude\|all\|none>] [--skip-integrations] [--skip-v4-cleanup]` | Post-install finisher: authenticated delivery, v4 cleanup, non-Codex convergence, skills channel. `--integrations` defaults to `auto` and is a `.choices()` option, so an unknown mode is refused at parse time with a one-line error naming the allowed values (exit 1) rather than a stack trace; `--skip-integrations` is an alias for `--integrations none`. Any mode but `none` installs to every agent **detected** on the host — one whose product home already exists, or whose skills home the previous record names. Genie never creates a product home |
| `setup [--orchestration-mode <standalone\|orca>] [--shortcuts] [--show] [--reset]` | Configure Genie and select the lifecycle authority |
| `config get <dotted.key> [--json]` | Read one schema key from the resolved config. `--json` adds `{key, value, source}` |
| `doctor [--fix] [--fix-global-db] [--json]` | Diagnostics. `--fix` backs up and removes proven v4 residue and merged-clean `genie launch` worktrees, and tightens registered-worktree modes (files only from wider to their index mode, dirs only 0775/0777 → 0755); it refuses replacements, symlinks, and non-wider or ambiguous modes, and is idempotent. `--fix-global-db` is a separate repair that runs **alone**, not with the other checks |
| `shortcuts show\|install\|uninstall` | tmux and shell keybindings |
| `update [--stable\|--dev] [--rollback]` | Update from a GitHub Release |
| `uninstall` | Record-driven, digest-verified removal |
| `help [command]` | Help |

### Verification, in one paragraph

`genie update` verifies a public release with **no GitHub credential**. The mandatory half runs in-process from the
release's own signed delivery evidence: the `<tarball>.<channel>.delivery.json` descriptor plus its `.sigstore.json`
bundle, checked against the embedded public-good Sigstore trust root with the publishing workflow's certificate
identity and the GitHub OIDC issuer pinned, the `delivery-evidence/v1` predicate type required, the DSSE subject
required to equal sha256 of the exact descriptor bytes, and the descriptor's `artifactSha256` bound to sha256 of the
downloaded tarball **before anything is extracted**. `gh attestation verify` is then an advisory cross-check, never the
gate: its failures split into `unavailable` (no gh, gh too old, no credential, network or timeout → one transcript line,
update proceeds) and `failed` (gh ran and says the artifact does not verify → abort). Missing or tampered delivery
evidence aborts before the cross-check, so an unauthenticated host can never be talked into skipping the floor.

### Doctor's output is aggregated

Every doctor surface prints **one line per check**, never one per item, with the full list under `--json`:

- `skills: <agent> <present>/<total> @ <ref>` per known agent skill home, plus one `agent dirs` completeness line.
- `skills: retirement` and `skills: legacy leftovers`, each naming at most five entries plus a remainder.
- `mode drift`, one summary line naming at most five entries; every entry rides `--json` under
  `checks[].modeDrift.entries`.
- `budgets: maxEscalationsPerGroup=<n> (<default|file>)`, read-only — doctor never writes a config file.

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Success |
| `1` | The command ran and did not succeed |
| `2` | **The operator must act.** The workspace gate, `mikro call`'s and `mikro fixtures`' usage refusals, `wish lint`'s refused root, and the **`ORCA_FORBIDDEN`** verbs under Orca authority |

## Orca mode refusals

`ORCA_FORBIDDEN` is a closed set: `task` (every subverb **except** `sync`), `board`, `idea`. Nothing else. A second,
non-exempt commander `preAction` refuses those verbs before the handler with exit 2 and one fixed message naming `orca`
and the remedy `genie setup --orchestration-mode standalone`.

<Warning>
  **Exit 2 is the `ORCA_FORBIDDEN` set, not "every Orca refusal."** `genie context`'s own refusal — every form except
  `--wish <slug> --plan` — is raised by the handler, not by the preAction, and exits **1**. Scripting for "2 means
  Orca said no" is wrong for `context`.
</Warning>

Two deliberate carve-outs:

- `task sync` exits **0, silent**, with the check placed before the workspace guard, so the pre-commit hook prints no
  `board snapshot not refreshed` warning on every commit.
- `context --wish <slug> --plan` answers read-only, exit 0, with no write path reachable. Every other form of
  `genie context` still refuses. This reverses the earlier "every form degrades identically" rule by explicit owner
  decision.
