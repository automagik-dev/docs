# Genie Architecture

Engineering-internal view of how the pieces fit. The operator-facing version is
[Architecture → Overview](/genie/architecture/overview).

## No service topology

There is none, and that is the design. Genie has **no daemon, no server, no port, and no resident process**. Every
command forks, opens what it needs, runs one transaction, and exits.

The v4 topology — an embedded PostgreSQL instance (pgserve), a NATS event spine, a scheduler daemon, tmux pane
orchestration, executor registries, a full-screen console, and a desktop app — was removed in the cutover to the
lightweight body. v4 is preserved on the [`v4` branch](https://github.com/automagik-dev/genie/tree/v4).

## The one database per scope rule

There is exactly **one** lifecycle database, and it is per-repository.

| Database | Module | Scope |
|----------|--------|-------|
| `<repo>/.genie/genie.db` | `v5/genie-db.ts` | Tasks, dependency edges, lanes, wish-group execution state |

Worktrees resolve it through `git rev-parse --git-common-dir`, so all linked worktrees of one repository share it and a
task created in one is immediately visible in another with no sync step. It uses WAL and a `busy_timeout`, so concurrent
writers surface clean claim conflicts rather than `SQLITE_BUSY` flake.

v6 opens **no machine-scope lifecycle database**. The global `~/.genie/genie.db` existed only to hold the Omni approval
queue and inbox; with Omni removed there is nothing for it to hold.

### Schema versioning

`CURRENT_SCHEMA_VERSION` is **2**. The ladder lives in `sqlite-open.ts`'s `initOrValidate`: `OpenSqliteOptions.migrations`
is an array of `{from, to, apply}` applied in ascending `from` order when `version < schemaVersion`, each step in one
transaction, re-stamping `PRAGMA user_version` at the end. **After the ladder runs the database falls through to the
current-version branch** — `schemaIsCurrent`, then `ensureSchema` — so additive backfills still apply to a
just-migrated database exactly as they do to one already at `schemaVersion`. An unbridgeable gap still throws
`ForeignDbError` rather than guessing.

The 1 → 2 step drops the machine-local `hire_roster` table. `task import` of a snapshot that still carries the key
ignores it rather than failing.

## Lifecycle authority

Authority is an **explicit mode**, never inferred. `standalone` is the default, including when `orchestration.mode` is
absent; installing or opening Orca changes nothing.

`genie setup --orchestration-mode orca` probes the shipped plugin payload and a compatible Orca runtime before
atomically switching. After that, Genie refuses local `genie.db` lifecycle reads and writes and refuses roadmap writes,
syncs, and exports. Switching back imports no Orca state. **There is no fallback database in either direction** — if
Orca is unavailable, the operation fails.

The refusal is a second, non-exempt commander `preAction`, not the workspace hook: `WORKSPACE_EXEMPT` exempts exactly
the verbs `ORCA_FORBIDDEN` names, so the workspace hook can never carry the check.

```text
ORCA_FORBIDDEN = { task (every subverb except sync), board, idea }
```

## Delivery

Three surfaces, three delivery paths, one record each.

1. **The binary** — `install.sh`, then `genie update`. Verified offline from the release's own signed delivery evidence
   before extraction; `gh attestation verify` is an advisory cross-check whose `unavailable` failures never block.
2. **The skills** — the pinned skills.sh CLI run over the **local delivered tree** under `$GENIE_HOME/skills`, never a
   GitHub ref. Retirement of what this release drops runs **before** the install pass, backup-first and EXDEV-safe.
   The record at `$GENIE_HOME/skills-install.json` is `genie uninstall`'s removal authority and `genie doctor`'s
   comparison basis.
3. **The Orca plugin** — published as a tree-only git ref whose root *is* `plugins/genie`, because Orca's loader rejects
   any install tree containing a symlink and the repo root has `docs -> .docs-vendor/genie`.

Post-delivery convergence is an **argv-only handoff**: `genie update` invokes the freshly installed binary as
`update --post-delivery-converge`. Pre-contract binaries reject that at commander parse time, which is the whole point —
an environment-variable-only signal was ignored by an old target once, and it performed a second full update.

## Key design decisions

- **Documents in git, state in SQLite.** A human reviews a plan as a diff; a machine reads the ready set as a query.
  Neither is asked to do the other's job.
- **Reviewer ≠ engineer.** The review verdict is independent evidence. A chat verdict never advances state — the
  orchestrator persists it into `WISH.md` and is the only actor that runs `task done`.
- **Nothing runs inside the agent's event loop.** No hooks, no MCP server, no injected session context. A Genie release
  cannot block, rewrite, or delay a tool call.
- **Aggregate the report, keep the list.** Every doctor and installer surface prints one line per check and carries the
  full list under `--json` or in the record. Per-item output has twice hidden a real failure in noise.
- **Backup before you remove, and prove before you delete.** Every removal path — skills retirement, legacy leftovers,
  `init`'s config rewrites, `uninstall` — copies first, acts only on what it can prove it owns, and reports what it
  preserved.
