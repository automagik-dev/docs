Your first wish is one decided task. `/wish` checks that the task fits a single wish, makes the change in its own git worktree, runs your repository's checks, has a different agent review the commit and opens a pull request. Merging stays with you.

## Before you start

- A git repository whose `origin` is on GitHub, and the GitHub CLI signed in (`gh auth status` says so).
- An integration branch on `origin` for the pull request to target. `/wish` uses `dev` unless you name another branch, and it refuses `main` and `master`.
- Checks your repository can run. The gate runs your full check when the repository has git hooks, and otherwise the validation command set for the task, so a wish proves what those checks prove.
- Claude Code, which runs `/wish` as a saved workflow. In Codex, `$wish` runs the same stages by hand.

## Your first wish

<Steps>
<Step title="Install and check">
  Install Genie (the [installation guide](/genie/installation) lists what the install needs), then run `genie doctor` inside your repository. Its `skills:` lines and its `workflows: catalog` line should pass.

  ```bash
  curl -fsSL https://raw.githubusercontent.com/automagik-dev/genie/main/install.sh | bash
  genie doctor
  ```

</Step>
<Step title="Prepare the repository">
  From the repository root:

  ```bash
  genie init
  ```

  `genie init` writes `.genie/INDEX.md` and the `.gitignore` rules that keep Genie's machine-local state out of git. Running it again changes nothing.
</Step>
<Step title="Ask for one task">
  Open Claude Code in the repository and give `/wish` one decided, bounded task. Name the files and the outcome you expect. This is the request from the run in the video below:

  ```text
  /wish Delete dead code: src/lib/defaults.ts has no production callers (only a type import of AgentDefaults in src/lib/workspace.ts) and src/__tests__/dir-ls.test.ts reimplements a removed handler and asserts on its own copy. Move the AgentDefaults type into workspace.ts, delete defaults.ts, defaults.test.ts and dir-ls.test.ts.
  ```

  The workflow runs in the background. `/workflows` in Claude Code shows its progress.
</Step>
<Step title="Read the report">
  The run ends in one state:

  | State | Meaning |
  |-------|---------|
  | `merge-ready` | The checks pass, the remote matches the local commit, the pull request holds exactly the declared files and the review says SHIP |
  | `pr-open` | The pull request exists but its checks had not finished; read them again with `gh pr checks` |
  | `refused` | Admission sent the task elsewhere and nothing was created |
  | `blocked` | Something stopped the run before or after publishing; the report names it |
  | `missed` | The repair budget ran out or a stage returned nothing; the branch, commit and worktree are kept |

  After every run the skill also runs `genie wish report <runId> --append`, which prints the run's tokens and time per stage.
</Step>
<Step title="Merge it yourself">
  Read the diff and the verdict, then merge the pull request. Genie never merges. The report ends with the command that removes the worktree and the branch after the merge; it refuses a branch that is not merged.
</Step>
</Steps>

## When `/wish` refuses

A read-only scout estimates the change and a judge that never sees the repository picks the route. A task that is too big, or that touches a trust boundary such as workflows, hooks, settings, release scripts or permissions, comes back `refused` with a route and nothing created:

| Route | What to do |
|-------|------------|
| `plan` | The task is too big for one pass or touches a trust boundary. Ask `/wish` for a plan and it writes a `WISH.md` for [work](/genie/skills/work) |
| `brainstorm` | A product decision is still open. Settle it with [brainstorm](/genie/skills/brainstorm) first |
| `report` | The cause is unknown. Find it with `/report` before asking for the fix |

## Bigger work

Work bigger than one task takes the whole loop: [brainstorm](/genie/skills/brainstorm) settles the design, [wish](/genie/skills/wish) writes the plan, [work](/genie/skills/work) builds it group by group, [review](/genie/skills/review) checks it against the plan and [fix](/genie/skills/fix) closes what review blocks. The [Introduction](/genie/index) shows the loop in one table.
