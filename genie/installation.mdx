<Note>
  Genie runs on **Linux** and **macOS**. Windows is not supported today (WSL2 works but is not on the tested matrix). You'll also need Node.js 18+ or Bun, Claude Code (or another agent), tmux, Git, and — recommended — the GitHub CLI.
</Note>

## Prerequisites

| Tool | Required | Purpose |
|------|----------|---------|
| [Node.js](https://nodejs.org/) 18+ or [Bun](https://bun.sh/) | Yes | Runtime for the CLI |
| [Claude Code](https://docs.anthropic.com/en/docs/claude-code) | Yes | AI agent backend (or swap for [Codex, Open Claw, or a BYOA adapter](/genie/concepts/byoa)) |
| [tmux](https://github.com/tmux/tmux) | Yes | Agent process management |
| [Git](https://git-scm.com/) | Yes | Version control and worktrees |
| [GitHub CLI](https://cli.github.com/) (`gh`) | Recommended | PR creation and issue tracking |

## Install Genie

Pick the path that matches how you manage tools on your machine. The one-line bootstrap is the fastest; npm/Bun are the most familiar; "from source" is for contributors.

### Homebrew (macOS / Linuxbrew)

<Warning>
  A first-class Homebrew tap (`automagik/tap/genie`) is on the roadmap but not published yet. Until then, macOS users can run the one-line bootstrap below — it auto-detects Homebrew and uses it to install any missing prerequisites (Node, tmux, gh). Track the tap rollout in the [GitHub release workflow](https://github.com/automagik-dev/genie).
</Warning>

```bash
# Coming soon — tap not yet public
brew tap automagik/tap
brew install automagik/tap/genie
```

### One-line bootstrap

The bootstrap script detects your system and installs via the best available method (including Homebrew on macOS for prerequisites):

```bash
curl -fsSL https://raw.githubusercontent.com/automagik-dev/genie/main/install.sh | bash
```

Genie installs in **two steps, and only two**:

<Steps>
  <Step title="Install the signed binary">
    Downloads and installs the signed `genie` release for your platform and links it onto your `PATH`.
  </Step>
  <Step title="Install the skills">
    The binary then runs the pinned [skills.sh](https://skills.sh) CLI against its own delivered skill tree, which writes Genie's skills — `wish`, `work`, `review`, `brainstorm`, and the rest — into every agent skill home skills.sh supports on this machine. `genie update` repeats this step on every update, so the skills on disk always match the binary you are running.
  </Step>
  <Step title="Run genie doctor">
    Verifies prerequisites, config, and the skills channel, then prints a green checklist (or tells you what's missing).
  </Step>
</Steps>

<Note>
  **Genie ships exactly one plugin, and it is the Orca plugin.** There is no Claude Code plugin, no plugin marketplace registration, and no editor-specific integration to install. Skills reach your agent through skills.sh; everything else is the signed binary.
</Note>

### npm

```bash
npm install -g @automagik/genie
```

### Bun

```bash
bun install -g @automagik/genie
```

### From source

```bash
git clone https://github.com/automagik-dev/genie.git
cd genie
bun install
bun run build
bun link
```

## Skills for any agent

Genie's skills are published through [skills.sh](https://skills.sh), so any agent that reads skills can use them — Claude Code, Codex, Cursor, and the rest. To install them machine-wide, for every agent skills.sh supports, with no prompts:

```bash
npx skills add automagik-dev/genie -g --all
```

The flags matter:

- `-g` installs at global scope, under your home directory. Without it the bare `npx skills add automagik-dev/genie` is **project-scoped**: it writes the skills into the current working directory and leaves nothing machine-wide.
- `--all` answers both the agent picker and the skill picker for you — it is shorthand for `--skill '*' --agent '*' -y` — and installs every Genie skill into every agent skills.sh supports for global installs, rather than prompting. Agents skills.sh does not support at global scope (currently Eve and PromptScript) are skipped.
- `--copy` writes plain files instead of symlinks — add it when your agent or sandbox does not follow links.

Starting with the release that ships the skills.sh channel, `genie update` performs this global install itself — run `genie doctor` to see whether your version reports the skills surface. On earlier versions, run the command above once and again after each update. The `npx skills add` command is also how people who want Genie's skills without the Genie CLI install them, and how you get a project-scoped copy inside a single repository.

### The public command tracks `main`, not a release

<Warning>
  `npx skills add automagik-dev/genie -g --all` installs the **repository's default branch (`main`)** — and it does so **regardless of any `@<ref>` suffix you add**. Writing `automagik-dev/genie@v5.260830.21` does not pin the tag: skills.sh 1.5.23 binds the third segment of its source spec to the *skill filter*, not to a git ref, so that spec resolves to `main`'s tree with a skill filter applied. A `#fragment` is the only ref form the CLI honours.

  The consequence: the public command tracks `main`, which can be ahead of or behind any published release. **`genie update` installs the exact delivered release** — Genie points the same CLI at the signed tarball's own skill tree under `$GENIE_HOME/skills`, a local path source that skills.sh does resolve correctly. If you need the skills that match your binary, use `genie update`, not the public command.
</Warning>

## Verify your install

Run the diagnostic tool to confirm the CLI, prerequisites, and local config are wired up:

```bash
genie doctor
```

```text
Genie Doctor
────────────────────────────────────────

Prerequisites:
  ✓ tmux
  ✓ jq
  ✓ bun / node
  ✓ Claude Code

Installer Resolution:
  ✓ Resolved binary ...

Configuration:
  ✓ Genie config exists ~/.genie/config.json
  ✓ Setup complete

Skills channel:
  ✓ skills: claude    25/25 @ v5.260831.6
  ✓ skills: agents    25/25 @ v5.260831.6
  ✓ skills: goose     not detected
  ✓ skills: windsurf  not detected

────────────────────────────────────────
```

### Reading the skills lines

`genie doctor` is a **read-only observer** of the skills channel. It compares the install record Genie wrote at `~/.genie/skills-install.json` against what is actually on disk under each agent's skill home, and reports the drift. It never installs, retires, or repairs anything — not even under `--fix`. `genie update` owns every mutation on this surface.

| Line | Meaning | What to do |
|------|---------|------------|
| `skills: <agent> <n>/<n> @ v<version>` | Every recorded skill is present in that agent's home, installed from release `v<version>` | Nothing |
| `skills: <agent> not detected` | That agent's config home does not exist on this machine — a perfectly healthy state, reported as a pass | Nothing |
| `skills: <agent> <n>/<m> @ v<version>` (warn) | Skills are missing from that home | `genie update` |
| `skills: <agent> <n>/<n> @ v<version> (stale, binary is v<newer>)` (warn) | The skills on disk came from an older release than the binary you are running | `genie update` |
| `skills: <agent> <n>/<n> @ v<version> (unrecorded)` (warn) | Skills are on disk but no install record exists, so Genie cannot say which release put them there | `genie update` |
| `skills: channel — no install record` (warn) | Genie has never installed the skills channel on this host | `genie update` |

<Note>
  **Restart required.** After any install or update, most agents only pick up new skills on the *next* session start. If a skill doesn't autocomplete, restart your agent session before assuming the install failed.
</Note>

## Updating

```bash
genie update          # Stable channel
genie update --next   # Development builds
```

<Note>
  `genie update` swaps the signed binary and then reinstalls the skills channel from the tree that shipped inside that release, so the skills on disk always match the binary. A failed skills install never rolls the binary back: the command prints the exact remedy, exits non-zero, and stays retryable. Run `genie doctor` afterwards to confirm the skills lines are green.
</Note>

## Uninstalling

```bash
genie uninstall
```

Uninstall is **record-driven and digest-verified**. It reads `~/.genie/skills-install.json` and, for each agent skill home that record names, deletes only the skill directories that record named *and* whose content still hashes to the digest recorded at install time. Then it removes the install record, runs the legacy collectors for assets older Genie releases left behind, removes the `~/.local/bin` CLI symlinks, and removes the global `~/.genie` directory.

What that means in practice:

- **Skills you added yourself are left alone.** A skill the record never named is structurally out of reach of the removal.
- **A directory Genie cannot prove is still its own is preserved, not deleted.** If you edited a Genie skill in place, or the record predates content digests, the directory stays and `genie uninstall` reports it. Data safety beats cleanliness.
- **A foreign directory that `--copy` overwrote at install time is not restored.** The install snapshots and backs up any foreign same-named skill directory before overwriting it, and tells you where the backup went — but uninstall does not put it back. Restoring it is a manual step.
- **If anything could not be removed cleanly**, uninstall keeps `~/.genie` and the install record so the whole operation stays retryable.
- It does **not** remove the npm/Bun package itself — the command will remind you to also run `bun remove -g @automagik/genie` or `npm uninstall -g @automagik/genie`.
- Your project's local `.genie/` state directory is preserved.

<Note>
  There is no plugin to unregister. Genie ships one plugin, the Orca plugin, and it is installed and removed through Orca — not through `genie uninstall`.
</Note>
