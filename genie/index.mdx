# You're the bottleneck, not your agents

<Note>
  **Research Preview** — We think orchestration is the missing piece between "AI can code" and "AI can ship." This is experimental software. APIs will change, things will break, and we're building in public because that's the only way to build something real. [Join us on Discord](https://discord.gg/automagik) to argue about it.
</Note>

## The problem isn't AI — it's context collapse

It's 11 PM. You have 7 tabs open. Each one is an AI agent. Each one is brilliant in isolation. And each one has completely forgotten what the others are doing.

Tab 1 refactored the auth module an hour ago. Tab 4 is still importing the old interface. Tab 6 is writing tests against a schema that Tab 2 changed twenty minutes ago. You've re-explained the project structure three times — once per agent, because none of them talk to each other.

You're not coding anymore. You're a human clipboard. Copy context from Tab 1, paste into Tab 4. Realize Tab 4 hallucinated an import path because it never saw the refactor. Fix it yourself. Open Tab 7 to deal with the merge conflict that Tab 3 and Tab 5 created by touching the same file simultaneously, each unaware the other existed.

This is what exhaustion feels like in 2026. Not "AI doesn't work" — AI works fine. The problem is that **you're the orchestration layer**, and you're terrible at it. Not because you're bad at your job, but because holding seven parallel execution contexts in your head while also doing the actual thinking work is a job for a system, not a person.

**This is context collapse.** Not a failure of any single agent, but the absence of anything holding them together. Seven brilliant musicians, no conductor, no sheet music, no shared key signature. The music is cacophony — and you're the one with the headache.

## Genie is the conductor

Here's the deal: you describe the work once and Genie handles the rest.

It doesn't replace your agents — it makes them actually work together. You capture your intent once. Genie broadcasts it to every agent that needs it, in a structured format they can all read. Then it runs the work in parallel — isolated worktrees, shared state, cross-agent messaging — so agents know what each other are doing without you playing telephone.

- **Capture once** — write a wish, define the scope, set acceptance criteria. Done. You never re-explain.
- **Broadcast to all** — every agent reads from the same plan, the same context, the same ground truth
- **Coordinated execution** — parallel work across isolated branches, no merge conflicts during development
- **Agents talk to agents** — Tab 4 knows what Tab 1 did, without you copying anything

You describe what you want. Genie breaks it into parallelizable work, assigns agents, manages state, and assembles a pull request. You review and merge. That's it.

```text
/brainstorm → /wish → /work → /review → ship
```

## Bring your own agent

Genie has opinions about orchestration. It has zero opinions about which AI you use. It's a protocol, not a vendor lock-in. Use whatever agent fits the job — or mix them on the same team.

| Agent | Setup | Best For |
|-------|-------|----------|
| **Claude Code** | Works out of the box | Deepest integration — skills as slash commands, plus the saved-workflow catalog |
| **Codex** | Works out of the box | OpenAI's agent — reads Genie's skills from the shared `~/.agents/skills` home |
| **Goose, Windsurf, and the rest** | Works out of the box | Any agent [skills.sh](https://skills.sh) supports gets the same skills, in its own skill home |
| **Custom (BYOA)** | Nothing to configure | Any CLI agent that reads a skills directory — bring your own |

The skills are runtime-neutral by construction: they name portable roles and let each runtime map them onto its own
native subagents. Genie installs no custom agent profiles and no hooks, so nothing it ships runs inside your agent's
event loop. Switch agents mid-project or mix them on the same wish — Genie cares that the work ships, not who does it.

  See the [Hacks page](/genie/hacks) for community patterns on provider switching, cost optimization, and BYOA configurations.
</Tip>

## What Genie actually does

| Capability | The Point | Why It Matters |
|------------|-----------|----------------|
| **Wishes** | Structured plans — scope, criteria, execution groups | You describe it once. Agents figure out the rest. And one decided task skips the plan entirely. |
| **Skills** | Composable prompt programs, runtime-neutral | `/brainstorm`, `/wish`, `/work`, `/review`, `/fix`, `/council` and the rest — as slash commands in Claude Code, by name anywhere else. |
| **Documents in git** | Wishes, designs, and the index are plain markdown | You diff, review, and version a plan like any other code. Nothing important is trapped in a database. |
| **One file of state** | Tasks, lanes, and dependency edges in a single per-repo SQLite file | No daemon, no server, no port. A command opens it, runs one transaction, and exits. |
| **Boards** | A kanban view derived live by query | `genie board` has no stored view state to go stale. `genie idea` drops a thought straight into the Idea lane. |
| **Orca authority** | Lifecycle ownership is an explicit, reversible choice | `genie setup --orchestration-mode orca` hands the lifecycle to Orca, with exit-2 refusals instead of a shadow copy — and no fallback database in either direction. |
| **Saved workflows** | A script catalog for procedures worth running the same way twice | Installed to `~/.claude/workflows` alongside the skills — `council`, `docs-audit`, `skill-intake`, and more. |
| **Microagents** | `genie mikro` — narrow agents with an answer schema | Validated JSON whose every citation is verified, with repo-first agents resolved behind a trusted root. |
| **Skills channel** | One install path to every agent | Genie's skills ship through skills.sh into every agent skill home on the box — `~/.claude/skills`, the shared `~/.agents/skills` that Codex reads, `~/.config/goose/skills`, `~/.codeium/windsurf/skills`. Nothing Genie installs runs inside your agent's event loop. |
| **Verified delivery** | Every release verifies offline, with no GitHub credential | Signed delivery evidence is checked against an embedded trust root and bound to the tarball's hash before anything is extracted. |

## How it works

Every feature follows the same lifecycle — vague idea to merged pull request, no detours:

<Steps>
  <Step title="Brainstorm">
    Explore the idea. Identify constraints, scope, and design decisions. The `/brainstorm` skill guides you through this interactively until the idea is crisp enough to plan.
  </Step>
  <Step title="Wish">
    One decided task is delivered end to end right here — its own worktree, the gate, an independent reviewer, a
    merge-ready PR — with no plan at all. Work that is bigger than one task becomes a `WISH.md` instead, with scope,
    acceptance criteria, and parallelizable execution groups. That document is the contract between you and the agents.
  </Step>
  <Step title="Work">
    Genie dispatches your agent's own native subagents per execution group, wave by wave in dependency order. Each one knows its scope, its criteria, and how to validate its own output; state changes serialize through the per-repo SQLite file rather than through a coordinator.
  </Step>
  <Step title="Review">
    A **different** subagent from the one that wrote the code validates the work against the wish criteria — reviewer ≠ engineer, so the verdict is independent evidence. It returns **SHIP**, **FIX-FIRST**, or **BLOCKED**, and a bounded repair loop runs up to the budget in your config.
  </Step>
  <Step title="Ship">
    The orchestrator persists the review evidence into `WISH.md` — a chat verdict alone never advances state — and opens a pull request targeting `dev`. You review and merge. The agents did the work; you made the decision.
  </Step>
</Steps>

## Where it runs

Genie is CLI-first, and stable on **Linux and macOS**. Both are covered by the release gate, so a change that breaks one
of them does not ship. Windows is not supported (WSL2 works but is not on the tested matrix).

If you want a visual surface, Orca is it: `genie setup --orchestration-mode orca` hands lifecycle authority to Orca
through a closed public boundary, and the Genie plugin puts the same verbs in Orca's palette. There is no separate Genie
desktop app and no Genie UI — that is a deliberate choice, not a gap.
