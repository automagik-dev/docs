# /fix — Fix-Review Loop

Resolve FIX-FIRST gaps from `/review`. Dispatch a fix subagent, re-review, repeat up to 2 loops, then escalate.

## When to Use

- `/review` returned a **FIX-FIRST** verdict with CRITICAL or HIGH gaps
- Orchestrator hands off unresolved gaps after execution review

## Flow

1. **Parse gaps** — extract gap list from FIX-FIRST verdict (severity, files, failing checks).
2. **Dispatch fixer** — send gaps + original wish criteria to fix subagent.
3. **Re-review** — dispatch review subagent to validate the fix.
4. **Evaluate verdict:**

| Verdict | Condition | Action |
|---------|-----------|--------|
| SHIP | — | Done. Return to orchestrator. |
| FIX-FIRST | loop < 2 | Increment loop, go to step 2. |
| FIX-FIRST | loop = 2 | Escalate — max loops reached. |
| BLOCKED | — | Escalate immediately. |

5. **Escalate (if needed)** — mark task BLOCKED, report remaining gaps.

## Escalation Format

```text
Fix loop exceeded (2/2). Escalating to human.
Remaining gaps:
- [CRITICAL] <gap description> — <file>
- [HIGH] <gap description> — <file>
```

## Dispatch

Fix and re-review are **separate dispatches** — never combined in one subagent.
Both go through the runtime's own subagent surface; Genie has no spawn command.

| Dispatch | Brief |
|----------|-------|
| Fixer subagent | The gap evidence, original criteria, owned files, validation command, and the remaining budget |
| Reviewer subagent | A different agent, read-only, re-reviewing the repaired scope against the same criteria |

## Task Lifecycle Integration

The fixer never changes task status and posts nothing to the card: the group
stays claimed through repair and review. The coordinator relays each verdict to
the card in the per-repo `.genie/genie.db`:

| Event | Command |
|-------|---------|
| Verdict of each re-review | `genie task comment <id> --worker orchestrator -- 'review: FIX-FIRST — <gap summary>'` |
| Fix accepted and validated | `genie task comment <id> --worker orchestrator -- 'review: SHIP — validation: <command> → pass'` |
| Escalation (max loops) | `genie task comment <id> --worker orchestrator -- 'blocked: fix loop exceeded — <route>'` |
| Escalation (no progress) | `genie task comment <id> --worker orchestrator -- 'blocked: identical gaps across loops — <route>'` |

Task integration is graceful — with no card, the fix loop runs unchanged from
the review evidence alone.

## Rules

- Never fix and review in the same session — always separate subagents
- Never exceed 2 fix loops — escalate, don't spin
- Include original wish criteria in every fix dispatch
- If identical gaps persist across loops, escalate immediately
