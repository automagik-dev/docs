<Note>
Every genie job moves through the same phases, and each has a gate. You can jump in at any phase; the skills that implement each one are listed below.
</Note>

## The phases

<CardGroup cols={3}>
  <Card title="Brainstorm" icon="lightbulb" href="/genie/skills/brainstorm">
    Explore a vague idea until it is concrete, and write a `DESIGN.md`. Driven by [/brainstorm](/genie/skills/brainstorm).
  </Card>
  <Card title="Design review" icon="clipboard-check" href="/genie/skills/review">
    An independent pass on the design, before anything is planned. Driven by [/review](/genie/skills/review).
  </Card>
  <Card title="Wish" icon="sparkles" href="/genie/skills/wish">
    Admit the work. One decided task is delivered end to end; bigger work becomes a `WISH.md`. Driven by [/wish](/genie/skills/wish).
  </Card>
  <Card title="Plan review" icon="list-check" href="/genie/skills/review">
    Gate the plan against its own criteria before execution starts. The same [/review](/genie/skills/review) skill.
  </Card>
  <Card title="Work" icon="hammer" href="/genie/skills/work">
    Execute the approved groups wave by wave. Driven by [/work](/genie/skills/work); FIX-FIRST gaps flow through [/fix](/genie/skills/fix).
  </Card>
  <Card title="Implementation review" icon="rocket" href="/genie/skills/review">
    A different agent from the one that wrote the code returns SHIP, FIX-FIRST, or BLOCKED. Then the PR.
  </Card>
</CardGroup>

## A one-shot lifecycle

<Steps>
  <Step title="Start with an idea">
    Open [/brainstorm](/genie/skills/brainstorm) if the idea is still fuzzy, or go straight to [/wish](/genie/skills/wish) if you already know the shape. New to the loop? The [onboarding walkthrough](/genie/onboarding) runs this sequence end to end.
  </Step>
  <Step title="Get the design reviewed">
    [/review](/genie/skills/review) reads the `DESIGN.md` under `.genie/brainstorms/<slug>/` and returns a verdict. The design review is mandatory — a wish is planned from a reviewed design, not from a conversation.
  </Step>
  <Step title="Admit the work">
    [/wish](/genie/skills/wish) takes it from there. **One decided task** it delivers itself: its own worktree, the gate, an independent reviewer, a merge-ready PR, no plan at all. Work bigger than one task becomes `.genie/wishes/<slug>/WISH.md` with IN/OUT scope, acceptance criteria, and execution groups — the artifact every downstream phase reads.
  </Step>
  <Step title="Gate the plan">
    [/review](/genie/skills/review) inspects the wish and returns **SHIP**, **FIX-FIRST**, or **BLOCKED**. Run [`genie wish lint`](/genie/cli/wish-lint) first — a structurally broken plan should fail in a second, not in review.
  </Step>
  <Step title="Execute the work">
    [/work](/genie/skills/work) dispatches the runtime's own native subagents per execution group, in dependency order, and runs each group's validation. FIX-FIRST findings are closed by [/fix](/genie/skills/fix) within a bounded repair budget.
  </Step>
  <Step title="Review, persist, ship">
    [/review](/genie/skills/review) runs again — as a **different** subagent from the one that wrote the code, so the verdict is independent evidence. A chat verdict never advances state: the orchestrator persists the evidence into `WISH.md`, is the only actor that runs `genie task done`, and opens the PR. You merge.
  </Step>
</Steps>

## Watching it happen

There is no monitoring skill, because there is nothing resident to monitor. State is a query:

```bash
genie board                 # the live kanban, derived by query
genie board --wish <slug>   # scoped to one wish
genie task status <id>      # one card: dependencies, stage log, assignment
```

## Entry points

| I want to... | Start at... | Skill or command |
|---|---|---|
| Explore a fuzzy idea | Brainstorm | [/brainstorm](/genie/skills/brainstorm) |
| Deliver one decided task | Wish | [/wish](/genie/skills/wish) |
| Plan work bigger than one task | Wish | [/wish](/genie/skills/wish) — its plan entry |
| Gate a design, a plan, or a PR | Review | [/review](/genie/skills/review) |
| Execute an approved wish | Work | [/work](/genie/skills/work) |
| Close FIX-FIRST gaps | Work | [/fix](/genie/skills/fix) |
| Check a plan's structure before anyone acts | Any | [`genie wish lint`](/genie/cli/wish-lint) |
| See where everything stands | Any | [`genie board`](/genie/cli/boards) |
| Run a batch of approved wishes overnight | Any | [/dream](/genie/skills/dream) |
