# Task Commands

`genie task` is Genie's lifecycle state machine. A **card** carries a title, an optional wish slug, an optional
board lane, a status, a dependency set and a timeline. Every subcommand opens the database, runs one transaction and
exits — there is no daemon, no server and no background writer.

State lives in `<repo>/.genie/genie.db`: SQLite via `bun:sqlite`, in WAL mode. Every linked worktree of a repository
resolves the same file through `git rev-parse --git-common-dir`, so a card created in one worktree is **immediately
visible in every other one**, with no sync step and no export in between.

<Note>
  This page describes **standalone** mode, the default. Under explicitly selected Orca authority
  (`genie setup --orchestration-mode orca`), every `genie task` subcommand except `sync` exits **2** with one fixed
  line naming the remedy `genie setup --orchestration-mode standalone`. `genie task sync` exits **0 and prints
  nothing**, so the git hooks that call it stay silent.
</Note>

## Subcommand inventory

| Subcommand | Purpose |
|------------|---------|
| `create` | Create a task |
| `link <id>` | Link an existing task to a wish (appends a wish event) |
| `set-wish <id>` | Attach, re-point, or clear the wish identity on a card |
| `assign <id>` | Declare which roster agent works a card, and why |
| `adopt <id>` | Place a laneless card onto a board lane (one-time) |
| `move <id>` | Move a card to a lane defined by its board |
| `checkout <id>` | Atomically claim a ready task for a worker |
| `heartbeat <id>` | Record a liveness heartbeat for a claimed card |
| `release <id>` | Release a claim, returning the card to the ready queue |
| `report <id> <text>` | Append the claimant's worker report to the card timeline |
| `comment <id> <text>` | Append an authored comment to the card timeline |
| `block <id>` | Place an enforced block on a card (refuses checkout until cleared) |
| `unblock <id>` | Clear an enforced block from a card |
| `done <id>` | Mark a task done and recompute the ready set |
| `delete <id>` | Permanently delete a card, its edges, and its timeline |
| `list` | List tasks with optional filters |
| `status <id>` | Show task detail, dependencies, and stage log |
| `export` | Emit the complete database state as JSON |
| `import [file]` | Restore database state from an export snapshot |
| `sync` | Reconcile `genie.db` with the canonical `.genie/roadmap.json` |

Card and board identifiers are opaque, time-sortable strings with a one-letter prefix — `t_…` for a task, `b_…` for a
board. There is no per-repo sequence number and no `#42` shorthand: pass the id as `list` or `status` printed it.

## Creating a card

```bash
genie task create --title <title> [--board <ref>] [--wish <slug>] [--group <name>] [--agent <name> --why <reason>]
```

| Flag | Description |
|------|-------------|
| `--title <title>` | Required. The card title |
| `--board <ref>` | Board id or name the card belongs to |
| `--wish <slug>` | Wish slug this card carries |
| `--group <name>` | Wish-group name (requires `--wish`) |
| `--agent <name>` | Declared roster agent: `claude`, `codex`, `pi`, `hermes` or `prime`. Requires `--why` |
| `--why <reason>` | Why that agent was declared. Requires `--agent` |

`--agent` and `--why` are a **pair**: either flag on its own is refused. The reason is not decoration — an assignment
with no recorded rationale is indistinguishable from a stale one three days later.

### Wish identity

`tasks.wish` is a **lifecycle slug**, not proof that a wish document exists. A card can carry the slug from the moment
`.genie/brainstorms/<slug>/` is created, and keeps it unchanged through Idea, Brainstorm, Wish, Work, Review and Done.
The slug is identity; the lane is progress.

```bash
genie task link <id> --wish <slug> [--group <name>]
genie task set-wish <id> --wish <slug> [--group <name>]
genie task set-wish <id> --clear
```

`link` requires a wish and attaches one. `set-wish` is the editing verb: it attaches, re-points, or — with `--clear` —
removes the wish and group. Both append a wish event to the timeline, so the card records when its identity changed.

## Declaring an assignment

```bash
genie task assign <id> --agent <name> --why <reason>
genie task assign <id> --clear
```

Assignment is **declaration-only**. It records who is expected to work the card and why; it is not a gate, and
`genie task checkout` does not consult it. The two are deliberately separate: the declaration is a plan, the claim is a
fact.

<Note>
  Assignment serializes on the **lane path only**. A reader that is not scoped to a lane — or a card that has no lane
  yet — deliberately does not see it. That is by design, not an omission: a laneless card has no place on a board for
  the declaration to mean anything.
</Note>

## Claiming and holding a claim

```bash
genie task checkout <id> [--worker <name>]
genie task heartbeat <id>
genie task release <id>
```

`checkout` is the **atomic claim**: exactly one worker wins, the rest are refused. It is the mechanism that keeps two
agents out of the same card. `--worker` defaults to `$GENIE_AGENT_NAME`, then `$GENIE_AGENT_ID`, then `cli`.

`heartbeat` takes **no** `--worker` — it records liveness for whoever already holds the claim, and there is no way to
heartbeat on someone else's behalf. `release` hands the card back to the ready queue.

## Moving a card between lanes

```bash
genie task move <id> --to <lane>
```

`--to` is required and names a lane **defined by the card's own board**. The flag is `--to`; there is no `--lane` on
`move`. Each move appends a move event to the timeline, so the lane history is recoverable.

A card created without a board has no lane. `adopt` is the one-time placement verb for those:

```bash
genie task adopt <id> --board <ref> --lane <name>
```

<Warning>
  `adopt` genuinely uses `--lane`, and `move` genuinely uses `--to`. The asymmetry is real: `adopt` names a board and a
  lane on it at once, while `move` only names a destination on the board the card already has.
</Warning>

## Blocking

```bash
genie task block <id> --reason <text> [--hold]
genie task unblock <id>
```

A block is **enforced**: `checkout` is refused while it stands. `--reason` is required, because a block with no stated
cause cannot be cleared by anyone but the person who set it. `--hold` records the block as a deliberate park rather
than a work problem — the distinction matters when you are reading a board and deciding what is stuck versus what is
waiting on purpose.

## The card timeline

Two verbs write prose onto a card, and they are not interchangeable.

| Verb | Author | Meaning |
|------|--------|---------|
| `report` | The current claimant | The engineer's handoff: outcome, what changed and where, how it was validated |
| `comment` | Anyone | The orchestrator's gate pointer: a review verdict, a done call, a blocked call |

```bash
genie task report <id> --worker <name> -- '<text>'
genie task comment <id> --worker <name> -- '<text>'
```

Use `--` before any text that starts with a dash, or the shell hands it to the parser as a flag.

`report` is the claimant's **one** handoff message per claim-to-handoff span; a fresh `checkout` opens the next span.
It is refused outright when the author is not the card's current claimant — that is what makes the report tag a trust
signal rather than a label anyone can apply. Both verbs are bounded at **4000 bytes** and reject control characters
(tab, newline and carriage return are text and survive verbatim), because the timeline crosses a board input contract
that holds the same bound.

## Finishing and deleting

```bash
genie task done <id>
```

`done` marks the card done and recomputes the ready set, promoting whatever was waiting only on this card.

<Warning>
  `genie task done` is **orchestrator only**. A reviewer verdict — SHIP, FIX-FIRST, BLOCKED — is *evidence*, never
  state. The orchestrator appends that evidence and then advances the card. A card that marks itself done on its own
  review has verified nothing.
</Warning>

```bash
genie task delete <id>
```

`delete` is a hard delete: the card, its dependency edges, its timeline and its stage log are removed outright. There
is no archive and no undo — the history survives only in whatever `.genie/roadmap.json` revisions git already holds. It
is **refused while another card depends on this one**, naming the dependents, because the edge table cascades: removing
a depended-on card would erase the edge instead of failing, leaving the dependent blocked by nothing and silently
promoting it to ready on the next recompute. Re-point or delete the dependents first.

## Inspecting

```bash
genie task list [--status <status>] [--board <ref>] [--wish <slug>] [--json]
genie task status <id>
```

| Flag | Description |
|------|-------------|
| `--status <status>` | Filter by `blocked`, `ready`, `in_progress` or `done` |
| `--board <ref>` | Filter by board id or name |
| `--wish <slug>` | Filter by wish slug |
| `--json` | Output as JSON |

`status` prints one card in full: detail, its dependencies, and its stage log. `--json` on `list` is the scripting
surface — pipe it to `jq` rather than parsing the human table.

## Snapshot, restore, reconcile

`.genie/roadmap.json` is the **canonical, git-tracked** board snapshot. `genie.db` materializes from it.

```bash
genie task export                # the complete database state as JSON, on stdout
genie task export --write        # write .genie/roadmap.json
genie task import                # restore from .genie/roadmap.json
genie task import --replace      # overwrite existing state instead of refusing a non-empty database
genie task sync                  # three-way reconcile in both directions
```

<AccordionGroup>
  <Accordion title="export / import">
    `export` with no flag writes JSON to stdout; `--write` takes an optional filename and defaults to
    `.genie/roadmap.json`. Plain `import` refuses a non-empty database rather than merging blindly; `--replace`
    rebuilds the database as exact snapshot state, which also means replaying an older snapshot resurrects cards that
    were deleted after it was taken.
  </Accordion>

  <Accordion title="sync">
    `sync` is a **three-way reconcile** between `genie.db` and `.genie/roadmap.json`, run by the git hooks on pull,
    merge, rewrite and pre-commit. It imports, exports, or warns on divergence, depending on which side moved. When
    both sides moved but the only difference is card timelines, the events are unioned by identity and republished as
    `merged` — the card conversation is global state: two engineers commenting on the same card from two worktrees are
    both right, and neither report should win by being merged second.
  </Accordion>
</AccordionGroup>

<Tip>
  Dependency edges and the ready set are part of the snapshot, not of any single command's flags. A card's status moves
  from `blocked` to `ready` when the cards it depends on reach `done` — which is why `genie task done` recomputes the
  ready set, and why `delete` refuses to orphan an edge.
</Tip>
