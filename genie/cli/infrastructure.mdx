# Infrastructure Commands

These are the commands that set Genie up, tell you whether it is healthy, and take it away again. None of them start a
service: Genie has **no daemon**. Every command opens what it needs, runs one transaction, and exits.

<Note>
  Genie's whole surface is **15 top-level commands**. Run `genie --help` for the live list — it is the only authority.
  This page covers the installation half; [Tasks](/genie/cli/tasks) and [Boards](/genie/cli/boards) cover the lifecycle
  half.
</Note>

## `genie init`

Scaffold per-repo state inside a trusted, initialized repository, and retire the historical project-level MCP
registrations Genie can **prove** it owns.

```bash
genie init
```

Two historical routes are retired, both backup-first:

| Route | What is retired | What is preserved |
|-------|-----------------|-------------------|
| `.codex/config.toml` | Only a Genie marker block. A file left holding nothing else is removed, with a `config.toml.genie-backup-<stamp>` beside it | Every other key, byte-for-byte |
| `.mcp.json` | Only a `genie` server whose command is a genie binary with args exactly `["mcp"]` | Every other server and key, byte-for-byte |

A symlinked config file is skipped rather than rewritten. `genie doctor` warns for as long as a dead entry is still
present.

## `genie install`

The post-install finisher. `install.sh` and `genie update` call it for you; you run it by hand only when an install was
interrupted.

```bash
genie install [--skip-v4-cleanup]
```

It performs the authenticated delivery, the v4 cleanup, and the non-Codex convergence — then converges the
[skills.sh](https://skills.sh) channel under the consent scope recorded at install time.

## `genie setup`

Configure Genie, including which lifecycle authority owns your board state.

```bash
genie setup [options]
```

| Flag | Description |
|------|-------------|
| `--orchestration-mode <standalone\|orca>` | Select the lifecycle authority. `standalone` is the default, including when the config omits `orchestration.mode` |
| `--shortcuts` | Only configure keyboard shortcuts (shell aliases + tmux keybindings) |
| `--show` | Print the resolved configuration |
| `--reset` | Reset settings to defaults |

Selecting `orca` first probes the shipped plugin payload and a compatible Orca runtime, then backs up your config and
switches atomically. It does **not** register the plugin with Orca — that is a separate, Orca-side install.

```bash
genie setup --orchestration-mode orca
genie doctor
```

In Orca mode Genie refuses local lifecycle mutation rather than keeping a shadow copy:

- `genie task`, `genie board` and `genie idea` exit **2** with one fixed line naming the remedy
  (`genie setup --orchestration-mode standalone`). That closed list of three root verbs is the whole list.
- `genie task sync` exits **0 and prints nothing**, so the git hooks that run it on every commit, merge and pull stay
  silent.
- `genie context --wish <slug> --plan` still answers, exit 0 with its JSON payload. It is strictly read-only and is the
  one question an agent needs answered to cut a worktree. Every other form of `genie context` refuses.

Switching back with `--orchestration-mode standalone` imports no Orca state. There is no fallback database in either
direction.

## `genie config`

Read the resolved global configuration. Read-only — it never writes a config file.

```bash
genie config get <dotted.key> [--json]
```

```bash Terminal
$ genie config get budgets.maxEscalationsPerGroup
2

$ genie config get budgets.maxEscalationsPerGroup --json
{"key":"budgets.maxEscalationsPerGroup","value":2,"source":"default"}
```

Every `budgets.*` key is a conservative default with a schema ceiling: configuration may only **tighten** a gate. A
hand-edited value past the ceiling fails the whole parse, so the resolved value falls back to the default and `source`
reports `default` — never the out-of-range number.

## `genie context`

Resolve spawn context as one line of versioned JSON, so an agent can cut a worktree without guessing.

```bash
genie context --wish <slug> [--group <g>] [--plan]
genie context                      # no wish: resolve the repo's integration branch
```

`--plan` previews the same payload with no side effects — it records no base and writes nothing.

## `genie doctor`

Diagnose the installation. Read-only by default, and read-only about the skills channel **always** — not even `--fix`
repairs it.

```bash
genie doctor [--fix] [--fix-global-db] [--json]
```

| Flag | Description |
|------|-------------|
| `--fix` | Tighten wider-than-index file modes inside registered worktrees |
| `--fix-global-db` | The one repair verb doctor owns: back up the global database and drop only the per-repo tables that do not belong in it |
| `--json` | Emit the full check payload, including every entry behind a summarized line |

```bash Terminal
$ genie doctor
Genie Doctor
────────────────────────────────────────

Prerequisites:
  ✓ git
  ✓ bun / node
  ✓ an agent that reads skills

Configuration:
  ✓ Genie config exists ~/.genie/config.json
  ✓ authority: standalone

Skills channel:
  ✓ skills: claude    19/19 @ v6.x.x
  ✓ skills: agents    19/19 @ v6.x.x
  ✓ skills: goose     not detected
  ✓ skills: windsurf  not detected

  ✓ mode drift: none found
  ✓ budgets: maxEscalationsPerGroup=2 (default)

────────────────────────────────────────
```

Doctor's output is **aggregated, never per-item**: a host with thousands of drifted worktree files prints one
`mode drift` line naming at most five entries plus a remainder, and `--json` carries every entry. The same rule governs
the skills lines and the legacy-leftover scan.

## `genie shortcuts`

Manage tmux keyboard shortcuts.

```bash
genie shortcuts show       # status
genie shortcuts install    # write to ~/.tmux.conf and your shell rc
genie shortcuts uninstall  # remove them again
```

## `genie update`

Update to the latest GitHub Release.

```bash
genie update [--stable | --dev] [--rollback]
```

The release is verified **offline, with no GitHub credential**, from the release's own signed delivery evidence: a
`delivery.json` descriptor plus its Sigstore bundle, checked against an embedded public-good trust root with the
publishing workflow's certificate identity pinned, and the descriptor's `artifactSha256` bound to the downloaded
tarball before anything is extracted. A `gh attestation verify` cross-check runs on top when a usable `gh` exists; a
host with no `gh` at all still updates, and prints one line saying the cross-check was unavailable.

After the binary is swapped, `genie update` converges the skills channel from the tree that shipped inside that
release — so the skills on disk always match the binary. A failed skills install never rolls the binary back: the
command prints the exact remedy, exits non-zero, and stays retryable.

## `genie uninstall`

Remove Genie, the recorded skills install, and the plugin-era leftovers the legacy collectors prove are Genie-owned.

```bash
genie uninstall
```

Removal is **record-driven and digest-verified**. A directory Genie cannot still prove is its own is preserved and
reported, never deleted. An unreadable install record refuses the whole plan — exit 1, nothing removed, `~/.genie` and
the record kept — rather than reporting a success that orphaned every skill directory.
